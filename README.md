# Dream Player — Windows frontend

Нативный интерфейс (C#, WinUI 3, unpackaged) поверх ядра
[`rs_dream_player`](https://github.com/ksimilikon/rs_dream_player) через его C ABI (`dream_player.dll`).

## Сборка (Windows)

1. Ядро (рядом, `..\rs_dream_player`):
   - на Windows: `.\scripts\build-core.ps1` (по умолчанию `origin/main`, `-Ref <ветка>` — другая).
     В ядре есть файлы `con.rs`, а `CON` — зарезервированное имя Windows, поэтому
     обычный checkout на Windows их не содержит и не собирается. Скрипт выгружает ref
     из git во временную папку (`%LOCALAPPDATA%\DreamPlayer\core-build`), сохраняет
     `con.rs` как `con_win.rs` с `#[path]`, собирает `cargo build --release` и кладёт DLL в
     `rs_dream_player\target\release\dream_player.dll` (прежняя — `.bak`). Сам репозиторий
     ядра не меняется;
   - или кросс-сборка с Linux: `cargo build --release --target x86_64-pc-windows-gnu`.
2. Фронтенд: `dotnet build DreamPlayer -c Release` (или открыть в Visual Studio 2022
   с workload «WinUI application development»). DLL ядра копируется к exe
   автоматически; другой путь — `-p:CoreDll=path\to\dream_player.dll`.

Требуется .NET 9 SDK, Rust (MSVC), Windows 10 1809+.

## Установщик

`.\scripts\build-installer.ps1` (нужен [Inno Setup 6](https://jrsoftware.org/isinfo.php),
`winget install JRSoftware.InnoSetup`) публикует приложение self-contained (.NET и Windows
App SDK внутри — на целевой машине ничего ставить не нужно) и собирает
`dist\DreamPlayer-<версия>-setup.exe`. Версия — `<Version>` в `DreamPlayer.csproj` или
`-Version 1.2.0`; DLL ядра — как при сборке, или `-CoreDll path\to\dream_player.dll`.
Установка по умолчанию для текущего пользователя (без прав администратора), установщик
предлагает и «для всех». При удалении данные в `%LOCALAPPDATA%\DreamPlayer` остаются.
UsbDk в установщик не входит.

## Структура

- `Core/` — P/Invoke (`Native.cs`, 1:1 с `api/src/*.rs`: `idx_*`, `engine_*`, `cdc_*`,
  `con_*`, `sync_*`), логируемая обёртка `CoreApi`, модели.
- `Services/` — плеер (очередь, shuffle/repeat, автопереход по колбэку ядра), библиотека,
  импорт/экспорт, лог взаимодействия с ядром, SMTC, настройки.
- `Services/Sync/` — транспорты синхронизации (ядро их не содержит, только протокол):
  TCP (Wi-Fi / сеть), ADB (`forward` / `reverse`), USB без adb (Android Open Accessory
  через WinUSB), Bluetooth RFCOMM (WinRT); `SyncWorker` гоняет байты между транспортом
  и сессией ядра и пишет полученные файлы.
- `Views/` — оболочка (вкладки, меню, нижняя панель) и вкладки.
- `L.cs` — строки RU/EN.

Данные: `%LOCALAPPDATA%\DreamPlayer` (`data` — база, конфиг и ключи устройства ядра,
`frontend.json` — настройки фронтенда). Схему базы ядро мигрирует само при запуске.
Лог фронтенда хранится только в памяти; во всех окнах с логами есть кнопка «Сохранить».

## Устройства и синхронизация

Меню › «Устройства и синхронизация»: двусторонняя синхронизация библиотеки с другим
устройством — оба получают все плейлисты и песни из них, удалённые плейлисты удаляются
и на другой стороне. Одна сторона ждёт подключения (она отдаёт библиотеку первой),
другая подключается; первое подключение связывает устройства (список связанных —
там же: переименовать / забыть). Экспорт умеет «Отправить на устройство» тот же выбор,
импорт — «Принять с устройства».

Подключения:

- **Wi-Fi / сеть** — ждать на порту (по умолчанию 47800; Windows может спросить про
  брандмауэр) или подключиться по адресу `host[:port]`. VPN с блокировкой трафика вне
  туннеля (WireGuard «Block untunneled traffic» при `AllowedIPs = 0.0.0.0/0`) запрещает и
  локальную сеть — на время синхронизации его нужно отключить или исключить LAN;
- **USB через adb** — нужен `adb` в `PATH` и отладка по USB на телефоне;
- **USB-кабель — Android** (Android Open Accessory, без adb; телефон выбирается из списка
  подключённых устройств, iOS / macOS в будущем — отдельными видами подключения): приложение само переключает телефон
  в аксессуар (запросы AOA 51/52/53), ждёт его повторного появления как `18d1:2d00` и
  работает с ним по bulk-каналам. Телефон обычно занят драйвером MTP, а Windows не даёт
  программам слать USB-запросы такому устройству, поэтому нужен
  [UsbDk](https://github.com/daynix/UsbDk/releases) (подписанный фильтр-драйвер, ставится
  один раз из x64 .msi): через него телефон на мгновение забирается у MTP для переключения,
  а аксессуар — на время сеанса. Устройство на WinUSB (adb с Google-драйвером, аксессуар,
  настроенный через Zadig) используется напрямую, без UsbDk;
- **Bluetooth** — устройства сначала связываются в настройках Bluetooth Windows; сервис
  синхронизации — RFCOMM с UUID `6f3c1a52-8d0e-4b8e-9a4b-3d2f7c51a9e1`.

## Песни вне плейлистов

Меню › «Песни вне плейлистов»: коллектор песен-сирот (не входят ни в один плейлист и
не синхронизируются). Фильтр: не отмеченные / оставленные / все. Отметка «Оставить»
(флаг ядра `ignore_orphan`, есть и в редакторе трека и в меню «Всех песен») убирает
песню из списка коллектора. Из коллектора и из «Всех песен» песню можно удалить с
устройства — файл с диска и запись из библиотеки.
